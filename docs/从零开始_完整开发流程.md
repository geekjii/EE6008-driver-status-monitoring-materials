# 从零开始：驾驶员面部疲劳感知系统完整开发流程

这份文档既是开发路线，也是学习路线。目标不是一次堆满所有功能，而是每一步都能运行、看见结果、解释原理并通过测试。

## 1. 最终目标

摄像头持续读取驾驶员面部画面，系统找到面部关键点，计算眼睛和嘴巴的状态，再利用真实时间窗口判断是否疲劳。

第一阶段输出：

- 是否检测到人脸；
- 眼睛开合程度；
- 是否正在打哈欠；
- 闭眼持续时间；
- 当前状态：`NORMAL`、`WARNING` 或 `DANGER`；
- 触发状态的原因和时间。

后续阶段再增加：

- 转头、低头和视线偏移；
- 看手机、喝水等动作；
- 视频文件批量分析；
- 可选的云端API和网页展示。

## 2. 本项目暂时不做什么

- 第一阶段不识别驾驶员身份，不判断“这个人是谁”；
- 不把一次眨眼直接判断成疲劳；
- 不承诺达到汽车安全产品或医疗设备标准；
- 不把摄像头画面自动上传到云端；
- 不在没有真实测试结果时宣称准确率。

## 3. 用大白话理解系统

整个系统可以理解成五个连续步骤：

```text
摄像头
  ↓
找到脸和眼睛、嘴巴的关键点
  ↓
计算 EAR（眼睛）和 MAR（嘴巴）
  ↓
用真实时间判断状态是否持续
  ↓
显示正常、警告、危险，并记录原因
```

MediaPipe负责找关键点，EAR和MAR负责把关键点变成数字，风险引擎负责理解这些数字持续了多久。

## 4. 为什么先在Mac本地实现

本地摄像头最容易观察和调试。第一阶段不依赖云服务器，也不需要NVIDIA显卡。只要Mac能够运行Python、OpenCV和MediaPipe，就可以验证完整流程。

代码从一开始就遵守跨平台规则：

- 使用`pathlib`处理路径；
- 摄像头编号、阈值和模型路径放在配置中；
- 不硬编码macOS目录；
- 算法逻辑不直接依赖窗口或摄像头；
- 保留视频文件输入，方便Windows/Linux和云端复用。

因此，“先在Mac跑通”不等于“只能在Mac运行”。

## 6. 核心概念

### 6.1 面部关键点

MediaPipe Face Landmarker会在脸上输出数百个坐标点。我们选择眼睛和嘴巴周围的少量点进行计算。

它解决的是“眼睛和嘴巴在哪里”，不是“这个人是谁”。

### 6.2 EAR：眼睛纵横比

EAR比较眼睛的垂直高度和水平宽度：

```text
EAR = 两组垂直距离之和 ÷ 两倍水平距离
```

- 眼睛睁开时，EAR通常较大；
- 眼睛闭合时，EAR会明显降低；
- 不同人的阈值不同，必须允许配置和校准。

### 6.3 MAR：嘴巴纵横比

MAR比较嘴巴张开的高度和宽度。

- MAR短暂升高可能是说话；
- MAR持续较高才更可能是打哈欠；
- 所以不能只判断单帧，需要时间窗口。

### 6.4 PERCLOS

PERCLOS表示一段时间内眼睛闭合所占的比例。它比“某一帧闭眼”更能反映持续疲劳。

### 6.5 状态机

状态机把连续数字转成稳定状态：

```text
NORMAL  → 短暂异常 → WARNING → 持续异常 → DANGER
   ↑                                      ↓
   └────────── 恢复一段时间后逐步返回 ────┘
```

这样可以避免摄像头偶尔识别错误导致报警闪烁。

## 7. 分阶段开发路线

### 阶段0：建立工程

要做：

- 创建Python项目结构；
- 建立配置文件；
- 建立自动化测试；
- 确保纯数学和时间逻辑不依赖摄像头。

完成标准：

- `python -m unittest discover -s tests`通过；
- 配置错误能够给出人能看懂的提示。

学到：一个项目为什么要分模块、为什么不能把所有代码写在一个文件中。

### 阶段1：摄像头和面部关键点

要做：

- OpenCV打开Mac摄像头；
- 每帧转为MediaPipe需要的RGB格式；
- Face Landmarker输出面部关键点；
- 画出人脸状态和FPS。

完成标准：

- 摄像头窗口能稳定打开和退出；
- 有脸时显示`FACE DETECTED`；
- 没有脸时不会崩溃；
- 关闭窗口后摄像头资源被释放。

学到：视频其实是一连串图片，实时系统就是逐帧处理。

### 阶段2：EAR和闭眼持续时间

要做：

- 计算左右眼EAR；
- 合并成平均EAR；
- 使用摄像头真实时钟累计闭眼时间；
- 区分眨眼和持续闭眼。

初始阈值只用于启动测试，最终要根据真人校准。

完成标准：

- 正常眨眼不会直接进入危险状态；
- 持续闭眼达到阈值后才报警；
- 不依赖固定FPS或固定帧数。

学到：为什么DriveEye的“45帧等于3秒”不够可靠。

### 阶段3：MAR和打哈欠

要做：

- 计算MAR；
- 判断嘴巴是否持续张开；
- 统计一定时间内的打哈欠事件；
- 与闭眼信号组合。

完成标准：

- 普通说话不会轻易触发持续哈欠；
- 哈欠开始和结束各记录一次，不会每帧重复记录。

学到：一个动作需要“开始、持续、结束”三个阶段。

### 阶段4：PERCLOS和风险融合

要做：

- 保存最近一段时间的眼睛状态；
- 按时间计算PERCLOS；
- 融合持续闭眼、PERCLOS和哈欠；
- 输出`NORMAL/WARNING/DANGER`及原因。

完成标准：

- 相同输入得到可重复状态；
- 多种风险同时出现时等级提高；
- 恢复后有稳定的冷却时间，不闪烁。

### 阶段5：界面、日志和本地交付

要做：

- 在画面显示EAR、MAR、PERCLOS、状态和原因；
- 支持摄像头和视频文件两种输入；
- 保存JSONL事件日志；
- 可选保存标注后的视频。

完成标准：

- 一条命令即可运行；
- 日志包含时间、状态、原因和原始指标；
- CPU模式能够运行。

### 阶段6：其他动作

按优先顺序增加：

1. 头部偏转和低头；
2. 视线离开道路；
3. YOLO手机检测；
4. 喝水、抽烟或其他课程需要的动作。

这些信号进入同一个风险引擎，不再另写一套报警系统。

### 阶段7：跨平台

验证顺序：

1. macOS本地；
2. Windows原生Python；
3. Linux；
4. 需要时再增加Docker。

每个平台至少验证：安装、摄像头、视频文件、测试和退出清理。

### 阶段8：云端

云端不直接读取本地摄像头。推荐分成两种模式：

- 批处理：上传视频，服务器分析后返回结果；
- API模式：本地程序只发送已提取的匿名指标或事件。

为了隐私，优先让原始人脸画面留在本地。只有用户明确同意时才上传视频。

## 8. Mac开发环境

推荐Python 3.11，并使用项目自己的虚拟环境：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

首次运行前下载MediaPipe Face Landmarker模型：

```bash
python scripts/download_face_model.py
```

运行自动化测试：

```bash
python -m unittest discover -s tests -v
```

打开摄像头：

```bash
driver-monitor-web
```

也可以在Mac上双击项目根目录中的`启动疲劳监测.command`，浏览器会打开本地仪表盘。`driver-monitor-gui`保留为Python桌面备用界面，`driver-monitor`保留为轻量调试窗口。

分析视频：

```bash
driver-monitor --video /完整路径/测试视频.mp4
```

如果Mac第一次请求摄像头权限，需要在“系统设置 → 隐私与安全性 → 摄像头”中允许当前终端或应用访问。

程序启动后会先校准约5秒。此时应正对镜头、正常睁眼并闭嘴。程序取较稳定的睁眼与闭嘴数据，自动为当前驾驶员生成EAR闭眼阈值和MAR张嘴阈值，再开始报警。这样比所有人共用一个固定阈值更可靠。

## 9. 配置而不是改代码

以下内容放在`configs/default.yaml`中：

- 摄像头编号；
- EAR闭眼阈值；
- 持续闭眼警告和危险时间；
- MAR哈欠阈值和持续时间；
- PERCLOS窗口和阈值；
- 状态恢复时间；
- 是否显示窗口、保存视频和写日志。

当判断不准确时，先调整配置并记录实验，不要随意在代码里改常数。

## 10. 测试方法

### 自动化测试

用人工构造的数据验证：

- 睁眼点计算得到较高EAR；
- 闭眼点计算得到较低EAR；
- 短暂闭眼不会报警；
- 持续闭眼会从警告进入危险；
- 时间窗口过期的数据会被移除；
- 恢复后状态能够下降。

### 真人本地测试

每个测试场景记录至少一次：

- 正常看镜头；
- 普通眨眼；
- 闭眼1秒、2秒、3秒；
- 模拟打哈欠；
- 说话；
- 戴眼镜；
- 光线较暗；
- 侧脸或脸离开画面。

不要为了测试在真实驾驶时闭眼。所有测试必须在静止、安全环境完成。

## 12. 最终验收标准

面部疲劳感知第一版完成必须同时满足：

- Mac摄像头能够运行；
- 支持本地视频文件；
- 检测人脸、EAR、MAR和PERCLOS；
- 使用真实时间而不是固定帧数；
- 输出稳定的三级状态和原因；
- 正常眨眼不会直接触发危险；
- 无人脸或模型缺失时给出明确提示；
- 事件日志能够复核；
- 自动化测试通过；
- README包含安装、运行、限制和隐私说明。
